# برداشت ما (Our Takeaway)

متن جلسه ← پیش‌نویس دوزبانه با هوش مصنوعی ← **تأیید ما در CMS** ← سایت + X + Reddit

```
 ترنسکریپت (رایگان، با ابزار خودمان)          ┌──────────── VPS (Docker) ────────────────────────────┐
 یا فایل صوتی + تیک Whisper (اختیاری) ──────▶│ Directus (CMS + Postgres)                            │
                                             │   │  هر تغییر در یک پست                                │
                                             │   ▼                                                  │
                                             │ n8n: workflow «Blog pipeline»                        │
                                             │   ├─ new/revise  → OpenRouter → پیش‌نویس fa+en → review │
                                             │   ├─ approved    → worker: build سایت → X → Reddit     │
                                             │   └─ archived    → worker: build بدون آن پست            │
                                             │                                                      │
                                             │ worker: astro build (پست‌ها را از Directus می‌خواند)    │
                                             │ Caddy: سایت استاتیک + HTTPS                            │
                                             └──────────────────────────────────────────────────────┘
```

| پوشه | چیست |
|---|---|
| `site/` | وبلاگ Astro، فارسی و انگلیسی با دکمهٔ تغییر زبان. پست‌ها را موقع build از Directus می‌گیرد. |
| `directus/` | اسکریپت راه‌اندازی CMS (collectionها، تنظیمات، Flow) و prompt پیش‌فرض |
| `n8n/` | workflow کامل به‌صورت JSON و [توضیح نود به نود](n8n/README.md) |
| `worker/` | سرویس کوچکی برای کارهایی که n8n خودش نمی‌کند: build سایت و Whisper |
| `docker-compose.yml`, `Caddyfile` | اجرای همه چیز روی سرور |

## روند کار برای ما

```
ضبط جلسه / فایل متن / لینک Drive
  → ۱ · تبدیل به متن      (ElevenLabs یا Whisper)
  → چند گوینده؟           (اسم‌ها را می‌پرسد، یا «ما» بنویسد)
  → ۲ · نوشتن پست         (به زبان خود جلسه)
  → ۳ · ترجمه             (به زبان دیگر + متن X و Reddit)
  → بازبینی ما            (در CMS یا تلگرام)
  → انتشار                (سایت + X + Reddit)
```

1. در Directus یک **Post** جدید می‌سازیم و یکی از این‌ها را می‌دهیم:
   - **فایل ضبط جلسه** در *Recording*، صوت یا ویدیو تا ۵ گیگ. از ویدیو فقط صدایش استفاده می‌شود.
   - یا **لینک Google Drive**. فایل باید «Anyone with the link» باشد. لینک مستقیم دیگر هم کار می‌کند.
   - یا **فایل متن جلسه** در *Or a transcript file*: ‏txt، md، srt، vtt، docx یا pdf. برای متن‌های طولانی بهترین راه است.
   - یا **متن آماده** در *Transcript*.
   - یا همهٔ این‌ها را **به ربات تلگرام بفرستید** (بخش تلگرام را ببینید).
2. اگر خواستید: زبان جلسه در *Language of the meeting* (خالی = تشخیص خودکار)، اسم‌ها و اصطلاحات در *Names and terms*، و مدل‌ها در بخش **0 · Progress and models**. بعد Save بزنید.
   - در *Notes* بنویسید کدام گوینده کیست، مثلاً `Speaker 1 = Sajad, Speaker 2 = Alireza`. آن‌وقت پست می‌تواند بگوید چه کسی چه گفت و نقل‌قول‌ها را به اسم درست نسبت دهد. اگر ننویسید، پست «یکی از ما» می‌نویسد.
3. پست خودش جلو می‌رود: *Transcribing…*، *AI is writing…*، *Translating…*، و بعد *Ready for review*.
   - پست **به زبان خود جلسه** نوشته می‌شود و بعد **به زبان دیگر ترجمه** می‌شود. جلسهٔ فارسی نسخهٔ انگلیسی هم می‌گیرد، و برعکس.
   - هر قدم در *Progress log* خود پست و در تلگرام ثبت می‌شود.
4. می‌خوانیم و ویرایش می‌کنیم: مستقیم در CMS، یا با فرستادن فایل ویرایش‌شده در تلگرام. برای بازنویسی با AI، در *Feedback* بنویسید چه چیزی عوض شود و وضعیت را **Revise with AI** بگذارید، یا در تلگرام به پیام پست جواب بدهید.
5. وضعیت را **Approved — publish now** بگذارید، یا در تلگرام ✅ Publish را بزنید.

### وقتی خطا پیش می‌آید

- وضعیت پست **Error** می‌شود. **متن کامل خطا** بالای پست نمایش داده می‌شود: کدام قدم، کدام نود n8n، پیام، جواب کامل خود API و لینک اجرای n8n. همین متن به تلگرام هم می‌رود.
- علت را برطرف کنید. مثلاً لینک را درست کنید، یا در *AI model (this post)* مدل دیگری انتخاب کنید.
- بعد وضعیت را **Retry** بگذارید، یا در تلگرام 🔁 Retry this step را بزنید. کار **از همان قدمی که خطا داده** ادامه پیدا می‌کند، نه از اول.
- برای شروع از قدم دیگری، *Restart from* را انتخاب کنید و بعد Retry بزنید:
  - **Transcription**: دوباره تبدیل به متن، مثلاً با مدل دیگر.
  - **Writing**: نوشتن دوباره.
  - **Translation**: فقط ترجمهٔ دوباره.
  - **Publishing**: انتشار دوباره.

### انتخاب مدل

- پیش‌فرض‌ها در **Writer Settings** هستند:
  - مدل AI برای نوشتن و ترجمه (هر مدل OpenRouter).
  - *Reasoning effort* و *Max output tokens*.
  - مدل تبدیل صدا به متن.
- هر پست می‌تواند در بخش **0 · Progress and models** مدل خودش را داشته باشد. در تلگرام هم دکمهٔ 🤖 Change model همین کار را می‌کند.
- اگر متن طولانی بود و خطای «ran out of output space» گرفتید:
  - مدلی با خروجی بزرگ‌تر انتخاب کنید، مثلاً `deepseek/deepseek-v4.1-flash` یا `deepseek/deepseek-v4-pro`.
  - یا *Reasoning effort* را Low کنید.
  - یا *Max output tokens* را بالاتر ببرید.
  - بعد Retry بزنید.
- مدل‌هایی که در تلگرام نشان داده می‌شوند در Writer Settings → *AI models offered in Telegram* و *Speech-to-text models offered in Telegram* قابل تغییرند.

## تلگرام

اگر `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` در `.env` باشند، تلگرام یک کنترل کامل برای CMS است. هر کاری که در Directus می‌شود کرد، از تلگرام هم می‌شود.

### کارت هر پست
- **هر پست یک پیام دارد** (کارت) که خودش به‌روز می‌شود، نه یک پیام برای هر قدم:
  ```
  #12 · عنوان پست
  🟩🟩🟨⬜⬜  40%
  ✅ Transcription · Persian · scribe_v2 · 42m 10s
  ✅ Writing · Persian · deepseek-v4-flash
  ⏳ Translating… · Persian → English
  ▫️ Review
  ▫️ Publish
  ```
- **وقتی کار با شماست** (آماده برای بازبینی، خطا، منتشر شد، از سایت برداشته شد) کارت به پایین چت می‌آید تا نوتیفیکیشن بگیرید. بقیهٔ قدم‌ها بی‌صدا همان کارت را عوض می‌کنند.
- **دکمه‌ها به وضعیت پست بستگی دارند:**
  - **آمادهٔ بازبینی:** ✅ Publish، ✏️ Ask for changes، 📄 Drafts، 🔁 Rewrite، 🌐 Re-translate
  - **منتشرشده:** 🌍 View، 🙈 Unpublish (با تأیید)، 📄 Drafts، ✏️ Ask for changes
  - **برداشته‌شده از سایت:** 🚀 Publish again، ✏️ Ask for changes، 🔁 Rewrite
  - **خطا:** 🔁 Retry، 🔄 Start over، 🤖 Change model، 📋 Full error
  - **همیشه:** ⚙️ Settings (🗣 گوینده‌ها و Notes، 🌐 زبان جلسه، 🤖 مدل AI و تبدیل صدا، 🗑 حذف پست با تأیید)، 📜 Transcript، 🔗 CMS
- کاری که پست منتشرشده را از سایت برمی‌دارد (Rewrite، Re-translate، Start over، Unpublish) قبلش تأیید می‌خواهد.

### چند گوینده: «چه کسی صحبت می‌کند؟»
- بعد از تبدیل به متن، اگر در ترنسکریپت **دو صدا یا بیشتر** باشد و در Notes هنوز `Speaker 1 = …` نیامده، کار **قبل از نوشتن می‌ایستد** (وضعیت *Who is speaking?*). کارت می‌آید پایین چت و از هر صدا چند جملهٔ اول را نشان می‌دهد تا بشناسید کیست.
- جواب‌ها:
  - **یک ضربه:** اسم‌های دفعهٔ قبل، به هر دو ترتیب، مثل `🗣 1 = Sajad · 2 = Alireza`
  - **✍️ Type the names:** یک اسم در هر خط، به ترتیب گوینده‌ها. جواب دادن به خود کارت با اسم‌ها هم همین کار را می‌کند.
  - **👥 Write it as “we”:** بدون اسم، همه‌چیز «ما»
- بعد از جواب، اسم‌ها به‌صورت `Speaker 1 = Sajad` در Notes ثبت می‌شوند و نوشتن خودش ادامه پیدا می‌کند.
- **در CMS:** Notes را پر کنید و وضعیت را **Retry** بگذارید؛ از نوشتن ادامه می‌دهد.
- اگر فقط یک صدا باشد، ترنسکریپت برچسب گوینده نداشته باشد، یا اسم‌ها از قبل در Notes (یا caption پیام تلگرام) باشند، چیزی پرسیده نمی‌شود.

### دیاگرام (Napkin AI)
- وقتی پستی آمادهٔ بازبینی شد، کارت می‌پرسد **«📊 Add a diagram?»**. با 📊 **Add a diagram**:
  1. AI کل پست را می‌خواند و بخشی از گفت‌وگو را انتخاب می‌کند که در متن سخت‌تر دنبال می‌شود (چند مرحله، چند گزینه یا چند جزء)، یا تصمیم اصلی جلسه را.
  2. برای آن متن دیاگرام را **کوتاه و دقیق** می‌نویسد: یک عنوان ۳ تا ۶ کلمه‌ای، ۳ تا ۶ مورد، و برای هر مورد یک برچسب ۱ تا ۳ کلمه‌ای و یک جزئیات ۳ تا ۸ کلمه‌ای با عدد، اسم و ابزارهای خود پست. کلمه‌های بی‌فایده حذف می‌شوند و همهٔ واقعیت‌ها می‌مانند. در صورت لزوم یک خط آخر «تصمیم:» یا «نتیجه:» هم دارد.
  3. **جای دقیق** را انتخاب می‌کند: پست با پاراگراف‌های شماره‌دار به AI داده می‌شود و AI می‌گوید دیاگرام بعد از کدام پاراگراف بیاید. معمولاً بعد از پاراگرافی که ایده را اول مطرح می‌کند (تا تصویر خواننده را در جزئیات بعدی همراهی کند)، یا بعد از پاراگرافی که آن را کامل می‌کند. وسط پست عادی است و آخر پست پیش‌فرض نیست. هیچ‌وقت بلافاصله بعد از تیتر یا داخل کادرهای برداشت و سؤال‌های باز نمی‌آید. اول چند کلمهٔ آن پاراگراف هم ذخیره می‌شود، تا اگر بعداً جای دیگری از متن ویرایش شد، دیاگرام کنار همان پاراگراف بماند.
  4. Napkin آن را برای هر زبان پست می‌کشد (PNG، با سبکی که در تنظیمات انتخاب شده) و تصویر در Directus ذخیره می‌شود. روی سایت به‌صورت یک کارت روشن با زیرنویس دیده می‌شود و با کلیک اندازهٔ کامل باز می‌شود.
- **دکمه‌ها:** 🖼 See diagram (تصویرها را در تلگرام می‌فرستد)، 🔁 New diagram، 🗑 Remove، 🚫 No diagram. اگر پست منتشر شده باشد، سایت خودکار دوباره بیلد می‌شود.
- **کردیت Napkin از کجا می‌آید:** طبق صفحهٔ قیمت Napkin «تقریباً ۱ کردیت برای هر کلمه‌ای که برای ساخت انتخاب می‌شود». یک بررسی عملی هم دیده که هزینه با تعداد کلمه‌هایی که در خود تصویر نمایش داده می‌شود بالا می‌رود (حدود ۲٫۷ کردیت برای هر کلمه). در هر دو حالت **کلمه‌های داخل تصویر** هزینه را تعیین می‌کنند. چون متن با حالت `preserve` فرستاده می‌شود، همان کلمه‌هایی که می‌فرستیم در تصویر می‌آیند. پس:
  - متن کوتاه و دقیق است. دقت از انتخاب ایدهٔ درست و کلمهٔ درست می‌آید، نه از تعداد کلمه.
  - فیلد `context` (متنی که فرستاده می‌شود ولی کشیده نمی‌شود) استفاده نمی‌شود، چون هزینه‌اش مستند نیست.
  - همیشه فقط یک نسخه ساخته می‌شود. 🔁 New diagram دوباره کردیت مصرف می‌کند.
  - کارت تلگرام بعد از ساخت می‌گوید چند کلمه رفته و تقریباً چند کردیت مصرف شده. برای اطمینان، بعد از اولین دیاگرام موجودی را در app.napkin.ai با همین عدد مقایسه کنید.
- **تعداد کلمه:** پیش‌فرض **۵۰ تا ۱۲۰ کلمه برای هر پست** است (۲۵ تا ۶۰ برای هر زبان)، یعنی حدود ۵۰ تا ۱۲۰ کردیت برای هر پست.
  - اگر متن AI از حداقل کوتاه‌تر باشد، یک بار دیگر واقعیت‌های جاافتاده خواسته می‌شود.
  - اگر از حداکثر بلندتر باشد، موردها از آخر حذف می‌شوند و عنوان و خط «تصمیم/نتیجه» می‌مانند.
  - از `/settings` → 📊 Words قابل تغییر است: ۴۰–۱۰۰، ۵۰–۱۲۰، ۸۰–۲۰۰ یا ۱۲۰–۳۰۰. در Writer Settings هم دو فیلد *Fewest / Most words per post* هست.
- **کلیدها:** `NAPKIN_API_KEY_1`، `_2` و `_3` در `.env`. اول کلید ۱ امتحان می‌شود. اگر نشد (کردیت تمام شده، کلید باطل شده، محدودیت، خرابی Napkin) کلید ۲ و بعد ۳ امتحان می‌شود و فقط وقتی همه شکست بخورند خطا می‌دهد. کلیدی که جواب داده یک ساعت اول امتحان می‌شود. خطای مربوط به خود متن کلید را عوض نمی‌کند.
- **پرامپت دیاگرام** هم مثل پرامپت نوشتن و ترجمه قابل ویرایش است:
  - **در Directus:** Writer Settings → *Diagrams* → **Diagram prompt**.
  - **در تلگرام:** `/settings` → 📄 Diagram prompt. فایل `diagram-prompt.md` می‌آید؛ ویرایشش کنید و در جواب همان فایل بفرستید. اگر ویرایش شده باشد، دکمهٔ ♻️ *Go back to the default* هم زیرش می‌آید.
  - **جای‌خالی‌ها** برای هر پست پر می‌شوند: `{{min}}` و `{{max}}` (بازهٔ کلمه برای هر زبان)، `{{target}}`، `{{languages}}` و `{{layouts}}`. اگر `{{min}}` و `{{max}}` را بردارید ربات هشدار می‌دهد، ولی بازه همچنان کنترل می‌شود.
  - **پیش‌فرض:** [directus/prompts/diagram.md](directus/prompts/diagram.md). خالی گذاشتن فیلد یعنی همین پیش‌فرض. دو پرامپت دیگر هم در تلگرام همین دکمهٔ برگشت به پیش‌فرض را دارند.
- **سبک:** `/settings` → 📊 Diagram style (Amber Harvest پیش‌فرض است و با رنگ‌های سایت جور است). هر style id از Napkin، حتی سبک شخصی خودتان، در Writer Settings → *Diagram style* هم کار می‌کند.
- در پلن رایگان Napkin، تصویرها واترمارک دارند.

### ویرایش
- **📄 Drafts** هر زبان را به‌صورت فایل `post-<id>.fa.md` / `post-<id>.en.md` می‌فرستد. فایل را ویرایش کنید و در جواب همان فایل بفرستید (اسم فایل را عوض نکنید). عنوان، توضیح، برچسب‌ها و متن آن زبان جایگزین می‌شود.
- **✏️ Ask for changes**، یا جواب دادن با متن به کارت: جوابتان Feedback می‌شود و AI پیش‌نویس را بازنویسی می‌کند.
- **🗣 Speakers & notes:** بنویسید کدام گوینده کیست (`Speaker 1 = Sajad`) و هر نکته‌ای که نویسنده باید بداند. سؤال و جواب بعد از ثبت پاک می‌شوند و نتیجه روی کارت می‌آید.
- جواب دادن به کارت با یک ضبط یا فایل متن جدید، آن پست را از اول (تبدیل به متن) دوباره می‌سازد.

### شروع پست جدید
یک ضبط صدا یا ویدیو (تا ۲۰ مگ، محدودیت خود تلگرام برای ربات‌ها)، یک فایل متن جلسه، یا یک لینک Drive بفرستید. خط اول caption (یا متن کنار لینک) عنوان پست می‌شود و خط‌های `Speaker 1 = …` به Notes می‌روند:
```
Story structure session
Speaker 1 = Sajad
Speaker 2 = Alireza
```

### دستورها
- `/posts`: همهٔ پست‌ها، از جدید به قدیم، با وضعیت. با زدن روی هرکدام کارتش پایین چت می‌آید.
- `/post 12`: کارت پست ۱۲.
- `/settings`: تنظیمات پیش‌فرض: مدل AI، reasoning effort، مدل تبدیل صدا، زبان پست‌های X و Reddit، 🔤 اسم‌ها و اصطلاح‌های همهٔ جلسه‌ها، و 📄 prompt نوشتن و ترجمه. prompt به‌صورت فایل می‌آید؛ ویرایشش کنید و در جواب همان فایل بفرستید تا جایگزین شود.
- `/help`: راهنما.

اینکه کدام پیام کارت کدام پست است در فایل `/data/telegram-cards.json` (volume `bot_data`) نگه داشته می‌شود، نه در Directus، پس به محتوای پست دست نمی‌زند. اگر این فایل پاک شود، کارت بعدی دوباره فرستاده می‌شود.
- **دسترسی:** فقط چت‌هایی که در `TELEGRAM_CHAT_ID` هستند می‌توانند از ربات استفاده کنند. چند id را با کاما جدا کنید، مثلاً گروه خودتان. اگر در یک چت دیگر `/start` بزنید، ربات id آن چت را می‌گوید.
- ربات webhook خودش را موقع شروع worker تنظیم می‌کند، روی `https://<CMS_DOMAIN>/telegram/webhook`.

## تبدیل صدا به متن

```
فایل آپلودشده یا لینک Drive → worker دانلود می‌کند → ffmpeg فقط صدا را نگه می‌دارد
→ ElevenLabs Scribe v2 (یا Whisper) → متن با «[زمان] Speaker n: …» → ادامهٔ workflow
```

- **ElevenLabs Scribe v2** پیش‌فرض است: روی فارسیِ قاطی با اصطلاحات انگلیسی از Whisper دقیق‌تر است، گوینده‌ها را جدا می‌کند و تا ۱۰ ساعت را در یک درخواست می‌پذیرد. زبان تشخیص‌داده‌شده ذخیره می‌شود و تعیین می‌کند پست اول به کدام زبان نوشته شود.
- ffmpeg از ویدیو فقط صدا را نگه می‌دارد (mono، Opus). یک ساعت ویدیوی حدود ۱ گیگی حدود ۱۵ مگ می‌شود و سریع آپلود می‌شود.
- **Whisper** (از طریق Groq، مدل `whisper:whisper-large-v3` یا `whisper:whisper-large-v3-turbo`) پشتیبان ارزان‌تر است و `TRANSCRIBE_API_KEY` را در `.env` لازم دارد.
- اسم‌ها و اصطلاحاتی که همیشه تکرار می‌شوند را در Writer Settings → *Names and terms (every meeting)* بنویسید.
- فایل‌های Google Drive خصوصی پشتیبانی نمی‌شوند. فایل باید با لینک قابل دسترسی باشد.
- فایل‌های آپلودشده روی سرور می‌مانند. اگر جا کم شد، بعد از انتشار از Directus → File Library پاکشان کنید.

## راه‌اندازی روی VPS

### ۱. DNS
سه رکورد `A` بسازید که همه به IP سرور اشاره کنند:

| آدرس | چیست |
|---|---|
| `blog.sajadsarlaki.com` | سایت عمومی |
| `cms.sajadsarlaki.com` | Directus، جایی که پست‌ها را بازبینی می‌کنیم |
| `n8n.sajadsarlaki.com` | ویرایشگر workflow |

### ۲. Swap
سرور ۴ گیگ RAM دارد و swap ندارد. Postgres، Directus، n8n و build سایت روی هم حدود ۱٫۵ گیگ می‌شوند، به‌علاوهٔ `rag-service` که الان روی سرور است:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### ۳. تنظیمات

```bash
git clone <this-repo> /root/meeting-blog && cd /root/meeting-blog && cp .env.example .env
```

در `.env` دامنه‌ها، ایمیل و رمز Directus، کلید OpenRouter، کلید ElevenLabs و شش مقدار تصادفی را پر کنید. هر مقدار تصادفی را با این دستور بسازید:

```bash
openssl rand -hex 32
```

### ۴. اجرا

```bash
docker compose up -d --build
```

```bash
docker compose logs -f directus-setup n8n worker
```

بار اول سرویس `directus-setup` جدول‌ها، تنظیمات، prompt و Flow را می‌سازد. n8n هم workflow را import و فعال می‌کند. Caddy گواهی HTTPS را خودکار می‌گیرد.

### ۵. بلافاصله بعد از اجرا

1. **`https://n8n.…` را باز کنید و حساب owner را بسازید.** تا این کار را نکنید، هر کسی که آدرس را باز کند می‌تواند owner شود.
2. **`https://cms.…`** را با ایمیل و رمز `.env` باز کنید. Directus 12 در اولین ورود دو سؤال می‌پرسد:
   - لایسنس: «I'm using Core plan» را انتخاب کنید (رایگان).
   - project owner: ایمیل خودتان را بدهید و شرایط لایسنس Directus (MSCL-1.0-GPL) را بخوانید و قبول کنید.
3. در **Writer Settings** مدل و prompt را ببینید و اگر خواستید تغییر دهید.

## X و Reddit (اختیاری)

اتصال این دو در خود n8n انجام می‌شود:

1. **X:** در developer.x.com یک App با OAuth 2.0 و دسترسی Read and write بسازید. Callback URL را این بگذارید:
   ```
   https://n8n.sajadsarlaki.com/rest/oauth2-credential/callback
   ```
   در n8n نود **Post on X** را باز کنید، credential جدید «X OAuth2 API» بسازید و Connect بزنید.
2. **Reddit:** در reddit.com/prefs/apps یک اپ از نوع **web app** با همان Callback URL بسازید. Reddit برای اپ‌های API جدید درخواست تأیید می‌خواهد. در n8n نود **Post on Reddit** را باز کنید و credential «Reddit OAuth2 API» بسازید.
3. در Writer Settings فیلد `reddit_subreddit` را پر کنید. `u_<username>` روی پروفایل خودتان پست می‌گذارد و امن‌ترین شروع است.
4. در `.env` مقدار `X_ENABLED=true` و/یا `REDDIT_ENABLED=true` را بگذارید، بعد:
   ```bash
   docker compose up -d n8n
   ```

## زبان سایت
- آدرس‌ها `/fa/...` و `/en/...` هستند و دکمهٔ بالای صفحه همان پست را به زبان دیگر باز می‌کند.
- انتخاب خواننده در یک cookie ذخیره می‌شود. کسی که اولین بار `/` را باز کند، بر اساس زبان مرورگرش به فارسی یا انگلیسی می‌رود.
- تشخیص زبان از روی لوکیشن (Geo-IP) پیاده نشده: به یک دیتابیس IP نیاز دارد و زبان مرورگر معمولاً دقیق‌تر است. اگر بعداً لازم شد، در Caddy قابل اضافه کردن است.

## توسعه و تغییر

- **workflow:** در n8n ویرایش کنید و Publish بزنید. روش برگرداندن تغییرات به repo در [n8n/README.md](n8n/README.md) است.
- **فیلدهای CMS:** در Directus از Settings → Data Model اضافه کنید، یا در `directus/setup.mjs` تعریف کنید تا روی نصب‌های تازه هم ساخته شوند.
- **دیزاین سایت:** `site/src/`، متن‌های ثابت در `site/src/consts.ts` و `site/src/lib/i18n.ts`. بعد از تغییر، روی سرور:
  ```bash
  git pull && docker compose up -d --build
  ```
  worker هر بار که بالا می‌آید سایت را از نو build می‌کند، پس همین یک دستور کد جدید و پست‌های تازه را منتشر می‌کند. تا وقتی build جدید تمام نشده، نسخهٔ قبلی سایت آنلاین می‌ماند (`docker compose logs -f worker` پیشرفتش را نشان می‌دهد).
  - `docker compose restart` هم سایت را دوباره build می‌کند، ولی **کد جدید را نمی‌گیرد**، چون image را از نو نمی‌سازد. برای کد جدید همیشه `--build` لازم است.
